Visao para Diretoria

O que e o Caculinha BI, em linguagem humana.

O Caculinha BI transforma perguntas em linguagem natural em respostas operacionais com dados, graficos e dashboards. Em vez de pedir relatorios para varias areas, o gestor conversa com o sistema.

Varejo Chat com dados reais Dashboard no proprio fluxo
"Pergunte como gestor. Receba como decisor."
01
Problema que ele resolve

O sistema encurta a distancia entre pergunta e decisao.

Antes

Muitas etapas

O gestor pergunta, alguem extrai dado, outra pessoa monta planilha, outra gera grafico.

Agora

Uma conversa

A pergunta entra no chat e o sistema devolve resposta, evidencias e visualizacao no mesmo fluxo.

Impacto

Mais velocidade

Menos dependencia operacional para chegar a uma leitura inicial do negocio.

02
A jornada em 5 passos

Uma pergunta atravessa o sistema assim.

Passo 1

O usuario pergunta

Exemplo: "Mostre os produtos com mais risco de ruptura no segmento Artes".

Passo 2

O sistema identifica quem esta falando

Ele entende qual usuario entrou e em qual contexto interno da Caçula esta respondendo.

Passo 3

O motor escolhe o melhor caminho

Decide se precisa consultar dados, gerar grafico, montar dashboard ou pesquisar mercado.

Passo 4

Os especialistas entram em acao

As funcoes do sistema executam a consulta e montam a resposta.

Passo 5

A resposta chega aos poucos

O chat vai mostrando progresso e entrega texto, tabela, grafico ou dashboard.

Para gestor: a leitura importante aqui e que o sistema nao responde "por chute". Ele passa por camadas e funcoes antes de falar.
03
Traduzindo a sopa de letrinhas

As palavras tecnicas que mais confundem, em portugues claro.

Tenant
Em palavras simples

É o contexto interno que o sistema usa dentro da própria Caçula.

Contexto por tenant
Em palavras simples

É o sistema lembrar em qual contexto interno da Caçula está respondendo naquele momento.

JWT
Em palavras simples

É o crachá digital do usuário. Sem ele, o backend não sabe quem está pedindo a informação.

SSE
Em palavras simples

É a resposta chegando em partes, sem esperar tudo ficar pronto no fim.

Tool
Em palavras simples

É uma função especializada: consultar dados, montar gráfico, pesquisar mercado.

Session ID
Em palavras simples

É o código da conversa atual. Ajuda o sistema a não perder o contexto.

Rate limit
Em palavras simples

É o limite de uso por tempo. Serve para proteger o sistema de excesso e abuso.

Role
Em palavras simples

É o perfil do usuário. Define o que cada pessoa pode ver ou fazer.

04
Anatomia do sistema

Se fosse uma operacao humana, o sistema seria assim.

Cockpit

Frontend

É a cabine de controle onde o usuário entra, navega e conversa com o sistema.

Portaria

Middlewares

É a camada que verifica identidade, contexto interno, limite de uso e rastreabilidade da requisição.

Cerebro

ChatServiceV3

É o maestro. Decide o fluxo e coordena a execução da resposta.

Especialistas

Tools

São os executores. Consultam dados, montam análises e produzem visualizações.

Fonte principal de verdade

Hoje, o coração operacional do sistema é o arquivo admmat.parquet, que guarda a base principal de análise.

05
Por que isso importa para gestao

Tenant aqui nao significa varias empresas. Significa contexto interno da Caçula.

Como a empresa é uma só, Caçula, tenant aqui significa o contexto interno em que o sistema está operando, ele consegue aplicar o ambiente correto, os limites corretos e, em certos casos, o recorte correto dos dados.

Sem contexto

O risco e misturar contexto interno errado, permissao errada ou configuracao errada.

Com contexto

O sistema responde no contexto interno certo, com o perfil certo e dentro dos limites certos.

Em frase unica

Contexto por tenant e o que impede a plataforma de tratar todas as situacoes internas da Caçula como se fossem iguais.

06
O que a diretoria deve observar

Quatro perguntas importam mais que o resto.

1
O sistema está respondendo rápido o suficiente para apoiar decisão?
2
As permissões estão corretas para cada perfil de usuário?
3
A base principal de dados está íntegra e atualizada?
4
Quando há falha, o sistema explica bem ou só quebra silenciosamente?
Boa gestão do produto aqui significa equilibrar velocidade, clareza, segurança e confiabilidade dos dados.
07
Riscos atuais

Os pontos que merecem cuidado executivo e tecnico.

Legado

Partes antigas convivem com partes novas

Isso aumenta o cuidado necessário antes de mudar autenticação, chat ou rotas.

Memoria local

Alguns limites e caches ainda são locais

Funciona, mas exige atenção se a operação crescer ou se o ambiente distribuir carga.

Dependencias externas

Parte do valor depende de provedores e fontes externas

Pesquisa de mercado e alguns fluxos podem variar conforme disponibilidade externa.

Permissoes

Controle de acesso é central

Qualquer erro de perfil, tenant ou segmento pode virar problema de governança.
